# 0001 訂單模組 - 需求分析

## 背景

商家「裱室 Bios Workshop」目前使用 Google 表單「Bios Workshop 訂購單」接單：客人到店與店員確認裱框內容後，自行填寫表單；表單中標示「(勿填)」的欄位再由店員補填。

本功能改由系統提供訂單：

1. 店員在系統中建立訂單資料。
2. 店員手機出示 QR Code 給客人掃描；從最後一次出示起 30 分鐘內可以進入填寫。
3. 客人用自己的手機掃描 QR Code，不需登入，填寫（編輯）客人資料。
4. 店員重新整理訂單頁，就能看到客人填寫的資料。

## 使用者故事

- **US-1** 身為店員，我想在與客人確認完工作項目後建立一張訂單，記下內容物、作品分類與成交資訊，以便之後追蹤製作與取件。
- **US-2** 身為店員，我想用手機顯示一個有時效的 QR Code 讓客人掃描，不需要把自己的手機交給客人。
- **US-3** 身為到店的客人，我想用自己的手機掃描 QR Code 後直接填寫聯絡資料並同意交易規範。
- **US-4** 身為店員，我不希望客人看到付款狀況與小備註、改到工作項目與店內欄位，也不希望超過填寫期限後還能被拿來修改資料。
- **US-5** 身為店員，我想查詢、查看、修改與刪除訂單，以便確認客人填寫的內容、更新付款狀況與交貨日期，並清掉建錯的訂單。
- **US-6** 身為店員，我想在之後查詢、修改訂單後重新出示 QR Code，讓客人確認最新的訂單內容並修改自己的資料。

## 名詞定義

- **訂單**：一位客人一次到店委託的內容。一張訂單只屬於一間商家。
- **訂單號碼**：店員在建立訂單時人工填寫，取代 Google 表單中的「工單號碼 (勿填)」。同一商家內不可重複（比對不分大小寫，`A001` 與 `a001` 視為相同），不同商家可以相同。建立後店員可以修改。
- **店內欄位**：只有店員能填寫的欄位，對應 Google 表單中標示「(勿填)」的欄位與「小備註」。客人看得到其中哪些見「欄位」一節。
- **填寫 QR Code**：店員在訂單明細頁出示的 QR Code，內容是該訂單專屬的填寫網址。
- **填寫期限**：每張訂單一個，等於最後一次出示 QR Code 的時間加 30 分鐘。每次出示都會把期限重新計算為從該次起 30 分鐘，並產生新的填寫網址；之前出示過的 QR Code 隨即失效，只有最後一次出示的 QR Code 可用。超過期限後，該訂單的填寫網址不能再開啟填寫頁。尚未出示過 QR Code 的訂單沒有填寫期限，視同逾期。

## 欄位

欄位名稱與選項依 Google 表單原文（2026-10-23 擷取）整理。選項以「」逐項標示（選項文字本身可能含有「、」「/」）。

勾選「其他」時必須輸入文字；未勾選「其他」時，「其他」文字框的內容不清除也不檢查。

### 工作項目（店員建立訂單時填寫，客人只能看）

| 欄位 | 必填 | 格式 |
|---|---|---|
| 本次裱框內容物 | 是 | 文字 |
| 作品分類 | 是（至少一項） | 複選 12 項：「一般裱框 (含證書框/相片/海報)」「無框裱 (油畫/輸出)」「書法、水墨畫」「壓模服務（冷裱）」「拼圖裱框」「絲巾裱框」「透明裱」「客製化設計 (含立體裱框)」「福音商品訂製」「訂製鏡子」「框物手作(黑板、網格、軟木留言板...等)」「其他」（可自行輸入文字） |

### 店內欄位（店員填寫）

客人在填寫頁看得到訂單號碼、成交金額、預計交貨日期；看不到付款狀況與小備註。

| 欄位 | 必填 | 格式 |
|---|---|---|
| 訂單號碼 | 是 | 文字；同一商家內不可重複（不分大小寫）；可修改 |
| 成交金額 | 是 | 非負整數 |
| 預計交貨日期 | 是 | 日期（日曆選取，預設為今天；只能選今天或之後的日期，修改時可保留原本的日期） |
| 付款狀況 | 是 | 文字（店員自行輸入） |
| 小備註 | 否 | 文字 |

### 客人欄位（客人填寫）

| 欄位 | 必填 | 格式 |
|---|---|---|
| 客戶姓名 | 是 | 文字 |
| 客戶手機 | 是 | 文字 |

## 驗收條件

### R1 建立訂單（US-1）

- **AC-1.1** 店員可建立訂單
  - Given 店員已登入並屬於該商家
  - When 在建立訂單頁輸入訂單號碼與內容物，勾選作品分類，輸入成交金額與付款狀況，按「建立」
  - Then 建立一張訂單，畫面進入該訂單的明細頁

- **AC-1.2** 必填欄位未填時不建立
  - Given 建立訂單頁
  - When 訂單號碼空白、內容物空白、未勾選任何作品分類、勾選「其他」但未輸入文字、成交金額空白或不是非負整數、付款狀況空白
  - Then 對應欄位顯示錯誤，「建立」按鈕不能按，不建立訂單

- **AC-1.3** 訂單號碼重複時不建立
  - Given 商家 A 已有一張訂單號碼為 `A001` 的訂單
  - When 店員在商家 A 以訂單號碼 `A001` 或 `a001`（不分大小寫）建立訂單並按「建立」
  - Then 不建立訂單，並在訂單號碼欄位顯示「訂單號碼重複」

- **AC-1.4** 訂單號碼只在同一商家內檢查重複
  - Given 商家 A 已有一張訂單號碼為 `A001` 的訂單
  - When 商家 B 以訂單號碼 `A001` 建立訂單
  - Then 建立成功

### R2 出示填寫 QR Code（US-2、US-4、US-6）

- **AC-2.1** 出示 QR Code
  - Given 一張訂單的明細頁
  - When 店員按「客戶填寫」按鈕
  - Then 該訂單的填寫期限設為現在起 30 分鐘，畫面顯示填寫 QR Code、訂單號碼與填寫期限的截止時間

- **AC-2.2** 期限內可以開啟填寫頁
  - Given 訂單仍在填寫期限內
  - When 客人以未登入的手機瀏覽器掃描最後一次出示的 QR Code
  - Then 不要求登入，直接開啟該訂單的填寫頁

- **AC-2.3** 逾期不能開啟填寫頁
  - Given 訂單已超過填寫期限（尚未出示過 QR Code 也視同逾期）
  - When 客人開啟該訂單的填寫網址
  - Then 不顯示表單與訂單內容，顯示「填寫連結已過期，請洽店員重新出示 QR Code」

- **AC-2.4** 再次出示會重新計算期限
  - Given 一張訂單，不論目前是否已超過填寫期限
  - When 店員再次按「客戶填寫」按鈕
  - Then 填寫期限重新設為從這次起 30 分鐘，並顯示新的 QR Code；先前出示過的 QR Code 失效，開啟時顯示「填寫連結已過期，請洽店員重新出示 QR Code」；已用先前的 QR Code 開啟的填寫頁，按「送出」時直接失敗，不儲存，顯示同一訊息

- **AC-2.5** 填寫網址無法被猜到
  - Given 知道某商家某張訂單的訂單號碼或其他訂單網址
  - When 不經 QR Code 自行組出填寫網址
  - Then 無法開啟任何訂單的填寫頁

### R3 客人填寫（US-3、US-4、US-6）

- **AC-3.1** 填寫頁只顯示客人需要的內容
  - Given 期限內的填寫頁
  - When 客人開啟
  - Then 顯示商家名稱、訂單號碼、工作項目（內容物、作品分類）、成交金額、預計交貨日期、客人欄位與交易規範；不顯示付款狀況、小備註，且訂單號碼、工作項目、成交金額、預計交貨日期都不能修改

- **AC-3.2** 客人送出
  - Given 客人填完所有必填欄位並勾選「沒問題，我已了解」
  - When 按「送出」
  - Then 儲存客人資料，畫面顯示送出成功的訊息

- **AC-3.3** 必填欄位未填時不送出
  - Given 填寫頁
  - When 任一必填欄位空白、「從哪裡認識 裱室 ?」未勾選任何一項、勾選「其他」但未輸入文字，或未勾選同意
  - Then 對應欄位顯示錯誤，「送出」按鈕不能按，不送出

- **AC-3.4** 期限內可以再次編輯
  - Given 客人已送出，且訂單仍在填寫期限內
  - When 客人重新開啟填寫頁
  - Then 客人欄位帶出上次送出的內容，「沒問題，我已了解」不預先勾選；客人重新勾選後再次送出，會覆蓋前一次的內容

- **AC-3.5** 填寫中逾期
  - Given 客人在期限內開啟了填寫頁
  - When 超過期限後才按「送出」
  - Then 不儲存，顯示「填寫連結已過期，請洽店員重新出示 QR Code」

- **AC-3.6** 客人不能修改店內欄位與工作項目
  - Given 填寫頁
  - When 客人送出
  - Then 只會更新客人欄位，訂單的工作項目與店內欄位不變

- **AC-3.7** 店員修改後重新出示，客人確認與修改
  - Given 一張客人已送出過的訂單，店員之後修改了工作項目、成交金額或預計交貨日期，並重新出示 QR Code
  - When 客人掃描 QR Code
  - Then 填寫頁顯示店員修改後的最新內容，客人欄位帶出上次送出的資料；同 AC-3.4，客人須重新勾選「沒問題，我已了解」才能送出，送出後覆蓋客人欄位

- **AC-3.8** Email 格式錯誤時不儲存
  - Given 填寫頁，所有必填欄位都已填寫並勾選同意，但客戶信箱不是正確的 Email 格式
  - When 按「送出」
  - Then 不儲存，並在客戶信箱欄位顯示「Email 格式錯誤」（Email 格式只在送出後由伺服器檢查，前端不檢查）

### R4 店員查看訂單（US-5）

- **AC-4.1** 重新整理後看到客人資料
  - Given 店員開著某張訂單的明細頁，客人已在填寫頁送出
  - When 店員重新整理明細頁
  - Then 顯示客人填寫的所有欄位

- **AC-4.2** 訂單列表
  - Given 商家有多張訂單
  - When 店員開啟訂單列表
  - Then 依建立時間由新到舊顯示訂單號碼、客人姓名、客戶手機、成交金額、預計交貨日期與付款狀況

- **AC-4.3** 查詢
  - Given 訂單列表
  - When 輸入訂單號碼、客人姓名或客戶手機的部分文字
  - Then 只顯示符合的訂單

- **AC-4.4** 只看得到自己商家的訂單
  - Given 店員屬於商家 A
  - When 以網址開啟商家 B 的訂單列表、明細或建立頁
  - Then 依既有權限設定拒絕存取

### R5 店員修改與刪除訂單（US-5）

- **AC-5.1** 修改工作項目與店內欄位
  - Given 任一訂單
  - When 店員修改訂單號碼、內容物、作品分類、成交金額、預計交貨日期、付款狀況或小備註並儲存
  - Then 儲存成功，必填與格式檢查同 AC-1.2，訂單號碼重複檢查同 AC-1.3（不與自己比較），其他欄位不變

- **AC-5.2** 刪除訂單
  - Given 任一訂單
  - When 店員在明細頁按「訂單取消」，進入刪除確認頁後按「確認刪除」
  - Then 訂單從列表中移除；該訂單的填寫網址開啟時顯示「此訂單已不存在」

- **AC-5.3** 刪除前要確認
  - Given 店員按了「訂單取消」
  - When 在刪除確認頁按「取消」
  - Then 訂單不刪除

### R6 入口（US-1）

- **AC-6.1** 店員可從後台進入訂單功能
  - Given 店員已登入並屬於該商家
  - When 在後台
  - Then 底部導覽與側邊選單都依序顯示「商家首頁、預約行事曆、訂單、系統設定」，點擊「訂單」進入訂單列表，並可從列表進入建立訂單

- **AC-6.2** 非商家成員看不到入口
  - Given 一般使用者（非該商家成員）
  - When 瀏覽商家首頁或預約頁
  - Then 底部導覽與側邊選單都看不到訂單入口

## 對既有行為的影響

以下依目前程式碼整理：

| 既有行為 | 變更內容 |
|---|---|
| 底部導覽（`Components/Shared/MainFooter.razor`）與側邊選單（`Components/Shared/MainSidebar.razor`）：員工目前看到「商家首頁、預約行事曆、系統設定」三項；非商家成員看到「商家首頁、預約紀錄」 | 兩處的員工選單都多一項「訂單」，放在「預約行事曆」與「系統設定」之間，共四項；非商家成員不變 |
| 權限設定（`appsettings.json` 的 `Authorization:Permissions`）：`/Companies/[CompanyId]/*` 只有該商家員工可存取；`/Sites/*` 所有角色可存取，但頁面多數要求登入（例如 `Sites/Appointments/NewPage` 為 `[Authorize]`），只有商家首頁是 `[AllowAnonymous]` | 客人填寫頁不需登入，會是商家首頁之外第二個允許匿名存取的頁面；授權改由有時效的填寫網址判斷 |

其餘既有行為（預約、行事曆、各項設定、客戶資料 `Customer`、估價工具、員工邀請 QR Code）不變。訂單的客人資料只存在訂單上，不寫入 `Customer`。

## 不在範圍內

- 寄送訂單副本或任何 Email 給客人（Google 表單目前會寄副件到客人信箱，系統版不寄）
- 取件通知（電話／簡訊／LINE）的發送
- 客人填寫後即時推播給店員（店員以重新整理查看）
- 由預約轉成訂單、訂單與預約串接
- 估價工具與訂單串接（帶入成交金額或材料明細）
- 訂單製作流程狀態（製作中、已完成、已取件等）
- 訂單列印、匯出 Excel／CSV
- 匯入 Google 表單既有資料
- 客人簽名
- 作品分類、住家區域等選項與交易規範由各商家自行設定（本版寫在程式中，所有商家共用）
- 寫入客戶資料（`Customer`）
- 店員更正客人欄位（客人欄位只由客人自行送出）
- MAUI App 的支援（MauiApp 沒有接 SQL 存取層，本功能只在 WebApp 驗收）

| Q6 客人可否在期限內重複送出 | 可以，期限內可再次編輯並覆蓋前一次內容；每次送出都要重新勾選同意交易規範（AC-3.4、AC-3.7） |

| Q4 再次出示 QR Code | 產生新的 QR Code，舊 QR Code 失效；填寫期限從最後一次出示起重新計算 30 分鐘（AC-2.4） |
| Q5 客人可否看到成交金額與預計交貨日期 | 可以看到，但不能修改（AC-3.1） |
| Q7、Q14、Q16、Q17 訂單號碼 | 店員人工填寫，必填；同一商家內不可重複；建立後可修改（AC-1.1–1.4、AC-5.1） |
| Q8、Q15 付款狀況 | 店員自行輸入文字（同 Google 表單） |
| Q10、Q18 入口位置 | 底部導覽與側邊選單，都放在「預約行事曆」與「系統設定」之間 |
| Q11 是否寫入客戶資料 | 不寫入，客人資料只存在訂單上 |

| Q19 同意時間與訂單狀態 | 不記錄交易規範的同意時間，也不顯示訂單狀態（待客人填寫／客人已填寫） |

| Q13 刪除或取消 | 店員可新增、查看、修改、刪除訂單與出示 QR Code；出示後填寫期限重新計算 30 分鐘 |

| 文字欄位長度 | 不設長度上限 |
| 前後空白 | 店員與客人輸入的文字欄位，儲存前去除前後空白；必填檢查以去除後的內容判斷 |
