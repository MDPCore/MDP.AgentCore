# 0002 最新消息置頂 - 需求分析

## 背景

商家在「最新消息」發布的公告，目前在商家首頁（`Sites/Home/IndexPage`）與店員的最新消息列表（`Companies/News/ListPage`）都依資料庫讀出的順序顯示，重要公告（例如店休、漲價通知）容易被後來的消息擠到下面。商家希望能把一則消息置頂。

## 使用者故事

- **US-1** 身為店員，我想把一則最新消息設為置頂，讓客人進入商家首頁時第一眼就看到。
- **US-2** 身為店員，我想取消置頂，讓消息回到一般排序。
- **US-3** 身為客人，我想在商家首頁最上方看到商家置頂的消息。

## 名詞定義

- **置頂消息**：被店員設為置頂的最新消息。每個商家同時最多一則。
- **置頂時間**：最後一次設為置頂的時間。

## 欄位

### 最新消息（店員填寫）

| 欄位 | 必填 | 格式 |
|---|---|---|
| 置頂 | 否 | 是／否（預設否） |

## 驗收條件

### R1 設定置頂（US-1）

- **AC-1.1** 店員可將消息設為置頂
  - Given 商家沒有置頂消息
  - When 店員在修改最新消息頁勾選「置頂」並儲存
  - Then 該消息成為置頂消息

- **AC-1.2** 同時只有一則置頂
  - Given 商家已有置頂消息 A
  - When 店員把消息 B 設為置頂並儲存
  - Then B 成為置頂消息，A 自動取消置頂

- **AC-1.3** 新增消息時可直接置頂
  - Given 建立最新消息頁
  - When 店員勾選「置頂」並建立
  - Then 新消息成為置頂消息，原本的置頂消息取消置頂

### R2 取消置頂（US-2）

- **AC-2.1** 店員可取消置頂
  - Given 消息 A 是置頂消息
  - When 店員在修改頁取消勾選「置頂」並儲存
  - Then 商家沒有置頂消息

- **AC-2.2** 刪除置頂消息
  - Given 消息 A 是置頂消息
  - When 店員刪除 A
  - Then 商家沒有置頂消息

### R3 顯示（US-1、US-3）

- **AC-3.1** 商家首頁置頂顯示
  - Given 商家有置頂消息
  - When 客人開啟商家首頁
  - Then 置頂消息顯示在最新消息的第一則，並標示「置頂」

- **AC-3.2** 店員列表置頂顯示
  - Given 商家有置頂消息
  - When 店員開啟最新消息列表
  - Then 置頂消息顯示在第一則，並標示「置頂」

- **AC-3.3** 其餘消息順序不變
  - Given 任何情況
  - When 開啟商家首頁或店員列表
  - Then 置頂以外的消息維持目前的顯示順序

## 對既有行為的影響

| 既有行為 | 變更內容 |
|---|---|
| `Companies/News/NewPage`、`UpdatePage` 只有內容與圖片欄位 | 多一個「置頂」勾選 |
| `Companies/News/ListPage`、`Sites/Home/IndexPage` 依 `NewsRepository.FindAllByCompanyId` 讀出的順序顯示 | 置頂消息移到第一則並標示「置頂」，其餘不變 |

## 不在範圍內

- 多則置頂、置頂排序
- 置頂期限（自動到期取消）
- 置頂通知推播

## 已決事項

| 項目 | 決定 |
|---|---|
| Q1 置頂數量 | 每個商家同時最多一則；設定新的會自動取消舊的（AC-1.2） |
| Q2 置頂時間是否顯示 | 不顯示，只用於記錄 |
